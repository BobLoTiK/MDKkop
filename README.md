# MDK — старт курса ML: лабы 02–04

Учебные скрипты по задачам 2, 3 и 4 (плюс проверка связи с локальной
нейросетью). Всё готово к запуску в VS Code на любой машине, где есть Python:
пути к данным и кодировка прописаны внутри скриптов, поэтому запускать их можно
откуда угодно.

## Что нужно один раз поставить

1. **Python 3.11 или новее** (проверено на 3.14) — https://www.python.org/downloads/ .
   На Windows при установке отметить галочку **Add python.exe to PATH**.
2. **VS Code** + расширение **Python** (id `ms-python.python`).
3. Пакеты — команды ниже. Для этих лаб хватает `numpy`, `pandas`, `matplotlib`,
   `seaborn`; `requests` нужен только для `hello_llm.py`.

## Быстрый старт в VS Code

1. Открыть эту папку: `File → Open Folder`.
2. В терминале VS Code (`Terminal → New Terminal`) создать окружение и поставить
   пакеты.

   **Windows (PowerShell):**
   ```powershell
   python -m venv .venv
   .venv\Scripts\activate
   python -m pip install --upgrade pip
   pip install numpy pandas matplotlib seaborn requests
   ```

   **macOS / Linux:**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   python -m pip install --upgrade pip
   pip install numpy pandas matplotlib seaborn requests
   ```

   `pip install -r requirements.txt` тоже сработает, но это полный замороженный
   список всего курса (torch, scipy, sklearn — примерно 2 ГБ). Для лаб 02–04 он
   не нужен.

3. Указать VS Code интерпретатор: `Ctrl+Shift+P` → **Python: Select Interpreter**
   → выбрать `.\.venv\Scripts\python.exe` (Windows) или `./.venv/bin/python`.
4. Запуск: открыть файл и нажать ▶ (**Run Python File**) либо в терминале
   `python stats.py`.

## Вариант без `.venv` (и что вообще обязательно)

`.venv` — это не требование, а удобство: он держит пакеты курса отдельно от
других проектов и фиксирует версии. Если изоляция не нужна, ставь пакеты в
системный Python и всё:

```powershell
pip install numpy pandas matplotlib seaborn requests
```

Минимум, который реально нужен по файлам:

| Файл | Импорты в коде | Что ставить |
|---|---|---|
| `stats.py` | `sys`, `pathlib` | **ничего** — только Python |
| `numpy_basics.py` | `numpy` | `numpy` |
| `prepare.py` | `pandas`, `matplotlib`, `seaborn` | `pandas matplotlib seaborn` |
| `hello_llm.py` | `requests` | `requests` + запущенная Ollama |

То есть одна только задача 2 (`stats.py`) идёт на «голом» Python 3.7+ без единого
пакета: он читает CSV вручную и ни от чего не зависит (проверено запуском
`python -S`, то есть с полностью отключёнными библиотеками). Остальным двум
скриптам нужны 3 пакета, обойтись без них не получится — это и есть предмет лаб.

Проверить, что уже установлено на машине:
```powershell
python -m pip list
```

Совсем без установки пакетов: любой онлайн-блокнот (Google Colab и подобные)
уже содержит numpy/pandas/matplotlib/seaborn — туда достаточно загрузить
`data/titanic.csv` и вставлять код ячейками. Минус: теряется работа с файлами
локально, а это часть заданий.

Про Linux/macOS: системный Python там часто защищён от `pip` (ошибка
`externally-managed-environment`). Тогда либо `.venv`, либо `pip install --user ...`,
либо `pip install --break-system-packages ...` (последнее — на свой риск).

## Что запускать и что должно получиться

Порядок — как в заданиях: 02 → 03 → 04.

### 1. `python stats.py` — задача 2 (≈2 секунды)

Читает CSV вручную (`open` + `split(',')`, без pandas), собирает столбцы в
словарь, считает n / mean / min / max для чисел и число уникальных для строк,
в конце печатает медиану возраста.

Ожидаемый вывод (фрагмент):
```
3 5 5 2.8
891 строк
survived     n= 891 mean=    0.38 min=   0.0 max=   1.0
age          n= 714 mean=   29.70 min=   0.4 max=  80.0
sex          n= 891 unique=2
Медиана возраста: 28.0
```
Зачем: тот же результат, что даёт pandas `describe()`, но видно, откуда берутся
числа — и почему у `age` n=714, а у остальных 891 (пропуски).

### 2. `python numpy_basics.py` — задача 3 (≈1 секунда)

Арифметика над массивом целиком, форма таблицы (`shape`), индексация
`M[0]`, `M[:, 1]`, `M[2, 3]`, транспонирование, `mean(axis=0)` / `axis=1`,
матричное умножение `A @ w`, broadcasting и линейная модель для 100 объектов:
`y = X @ w + b`.

Ожидаемый вывод (фрагмент):
```
[ 6  2  8  2 10] [13 11 14 11 15] [ 9  1 16  1 25]
2.8 1 5 14
(3, 4)
[4. 5. 6. 7.]        <- mean(axis=0): по одному числу на столбец (их 4)
[1.5 5.5 9.5]        <- mean(axis=1): по одному числу на строку (их 3)
[[-2]
 [-2]]               <- A @ w: (2,3) @ (3,1) = (2,1)
(100, 5) (5,) (100,)
29.69911764705882 0.42 80.0     <- титаник через numpy, как в задаче 2
```
Зачем: последняя строка (возраст из CSV одной строкой) — прямая стыковка с
задачей 2: раньше цикл, теперь один вызов. `axis=0` — «сжать строки», `axis=1`
— «сжать столбцы»; на этом ломаются чаще всего.

### 3. `python prepare.py` — задача 4 (≈5 секунд)

Читает Titanic в pandas, печатает `shape` / `head` / `info` / `describe`, считает
детей до 12 лет, заполняет пропуски (`age` — медианой, `embarked` — самым
частым), удаляет столбец `deck`, отвечает на три вопроса группировкой, рисует
графики и сохраняет `data/clean.csv` с новыми столбцами `family` и `sex_num`.

Ожидаемый вывод (фрагмент):
```
(891, 15)
68 0.5735294117647058          <- детей до 12 лет 68, из них выжило ~57%
sex
female    0.742038             <- выживаемость женщин ~0.74 (проверка из задания)
male      0.188908             <- выживаемость мужчин ~0.19
pclass
1    0.629630                  <- 1 класс 0.63, 2 класс 0.47, 3 класс 0.24
2    0.472826
3    0.242363
pclass  sex
1       female    34.0
3       male      26.9        <- средний возраст по классу и полу
```

Важно про графики: скрипт дважды вызывает `plt.show()`, открывается окно и
скрипт ждёт, пока ты его закроешь — это нормально, закрывай. Первое окно — три
графика (они же сохраняются в `titanic.png`), второе — гистограмма цены билета
для выживших и невыживших.

Если окна не нужны (или не открываются), запусти без интерактива:
```powershell
$env:MPLBACKEND='Agg'; python prepare.py     # Windows PowerShell
```
```bash
MPLBACKEND=Agg python prepare.py             # macOS / Linux
```
`titanic.png` и `data/clean.csv` при этом всё равно создаются, а в консоли
появится `FigureCanvasAgg is non-interactive` — это ожидаемо.

Ещё замечание: после заполнения пропусков в `embark_town` остаются 2 пустых
значения — так и задумано в задании, заполняются только `age` и `embarked`.

### 4. `python hello_llm.py` — необязательно

Отправляет запрос в локальную Ollama. Нужны сама Ollama и скачанная модель:
```
ollama pull qwen2.5:1.5b
```
Если Ollama не запущена или модели нет, скрипт не падает с трейсбеком, а
печатает подсказку, что именно сделать (`ollama list` покажет, что уже скачано).
Если в системе модель с другим тегом, имя можно подменить без правки файла:
```powershell
$env:OLLAMA_MODEL='qwen2.5:1.5b-instruct'; python hello_llm.py
```
Список моделей этого вида (`-instruct`) часто уже стоит на машине: тогда
докачивать `qwen2.5:1.5b` не нужно, достаточно переопределить `OLLAMA_MODEL`.

## Как это сделано переносимым

- Пути к данным считаются от расположения самого скрипта (`Path(__file__)`), а не
  от текущей папки, — `python stats.py` работает из любого каталога.
- Данные лежат в `data/`, как написано в заданиях; если csv всё-таки окажется
  рядом со скриптом, он тоже найдётся (запасной вариант в коде).
- `titanic.png` и `clean.csv` сохраняются рядом с исходными данными, а не в
  текущей рабочей папке.
- На старте скрипты переводят stdout в UTF-8 с `errors='replace'` — русский
  текст не роняет запуск на машине с другой локалью.
- `requirements.txt` перекодирован из UTF-16 в UTF-8 и починен: версий
  `torch==2.14.0+cpu` / `torchvision==0.29.0+cpu` на PyPI нет (они лежат в
  индексе PyTorch), из-за них `pip install -r requirements.txt` падал. Эти строки
  закомментированы, рядом в файле — команда для их отдельной установки.
- `.vscode/settings.json` фиксирует UTF-8 и автоактивацию окружения,
  `.vscode/launch.json` даёт запуск текущего файла из папки проекта (F5).

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| `ModuleNotFoundError: No module named 'pandas'` | окружение не активировано или VS Code взял другой Python → `Python: Select Interpreter`, затем перезапустить терминал |
| `FileNotFoundError: ...data\titanic.csv` | файла нет в `data/` — положить туда, имя строго `titanic.csv` |
| Вместо русского `?????` или ромбики | кодировка консоли: выполнить `chcp 65001` (Windows) и запустить снова |
| Скрипт «висит» после шага с графиками | открыто окно с графиком — закрой его |
| `FigureCanvasAgg is non-interactive` | запуск без GUI-backend, картинки всё равно сохранены |
| `ERROR: Could not find a version ... +cpu` | ставится старый requirements.txt; в текущем эти строки закомментированы |
| `Нет соединения с Ollama на localhost:11434` | запустить `ollama serve` и выполнить `ollama pull qwen2.5:1.5b` |
| Кракозябры, если вывод идёт через конвейер PowerShell | это особенность самого PowerShell; запусти просто `python stats.py` — в терминале вывод нормальный |
